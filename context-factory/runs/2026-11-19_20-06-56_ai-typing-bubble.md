## Goal

Replace processing-phase text with one animated assistant bubble only while an eligible customer/guest AI reply is pending. Preserve attachments, private-image validation, failures and retries; exclude human typing and AI-off interpretation.

## Result

Implemented across public, customer and admin conversation views. All work remains uncommitted. Terra agents implemented backend and UI; an independent Sol review found no remaining findings after corrections; the lead inspected integration and browser behavior.

## Changes or findings

- Shared `AssistantTyping` presentation, story and token-based styles provide accessible status labeling and reduced-motion static dots. Pending image slots use local thumbnails or neutral attachment text; phase labels are removed while error/retry controls remain.
- Existing job/message data derives `conversation.aiReplyPending` across pagination and `processing.replyPending` for acknowledgements. Eligibility checks activity/expiry, customer provenance, captured AI version, suppression and saved replies. No table or migration was added.
- Existing `reply_to_message_id` is exposed as `replyToMessageId`. Local text waiting is independent of delivery/outbox acknowledgement and settles by exact reply identity or request outcome. Multiple turns share one visible bubble; another conversation's pending state stays hidden.
- Version-aware merging, correlated-reply guards, serialized customer polls and admin request-generation guards prevent stale acknowledgements/polls from restoring settled state. Closed/expired threads hide the bubble. Root README and message rules describe current behavior.

## Decisions

Text waiting remains local to the sending client; reloads/other tabs do not restore in-flight text indicators. Background image waiting is server-derived. Re-enabling AI never revives an invalidated turn.
