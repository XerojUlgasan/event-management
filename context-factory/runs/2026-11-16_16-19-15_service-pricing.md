## Goal

Each service supports one fixed price covering a whole number of hours plus an excess hourly rate, or hourly-only pricing. Partial excess hours round up. Multiple fixed options were explicitly excluded by the user's correction.

## Result

The editor saves paired fixed-price/included-hours fields, or clears both for hourly-only pricing. Shared labels show the same terms on admin cards, customer cards, public cards and service details. Customers select fixed-price or hourly-only filtering before applying a price range. Quotations remain manually prepared.

## Changes or findings

- Added nullable integer fields to the existing service row, a paired SQL constraint and matching API validation. No pricing-options table or redundant stored mode is needed for a single fixed duration.
- The additive migration preserves every pre-existing service field, including hourly rates, timestamps and canvases. Legacy unknown rates remain readable. Browser/API service content uses the shared contract.
- Pricing type scopes filters and cursors; fixed ranges compare the base price, while hourly ranges exclude fixed services and compare hourly-only rates.
- Reused public UI Input, Select, FormField and Button exports and existing layouts/tokens. No shared control copies or style changes were needed.

## Decisions

Confirmed by the user: one fixed duration per service, whole included hours, excess-hour rounding up, separate filters, and service setup/catalog scope only. See [catalog rules](../business/catalog.md).
