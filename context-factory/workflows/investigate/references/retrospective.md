# Review lessons and prevent recurring mistakes

Use for a requested retrospective or recurring-mistake correction. Read accessible in-scope session evidence, commits, reverts, findings, and the current artifact. State missing raw evidence; a digest does not independently prove a claim.

1. Examine distinct lenses: judgment/assumptions, tooling/feedback, and missed alternatives. Use independent bounded read-only helpers only when authorized; otherwise disclose self-review.
2. Group supported repeated examples into mistake classes. One transient incident is not a recurring class. Reject duplicate lessons, unsupported generalizations, and unrelated proposals.
3. Prefer the strongest useful correction: canonical ownership/architecture → types or actionable checks → behavior tests → prose for remaining judgment. Prove enforcement rejects a representative mistake and accepts the valid case.
4. If the right guide was not discovered, fix its routing condition. If it was clear but ignored, another copy of its wording may not help. Update a method only when the method itself failed.
5. Apply only authorized changes. Retain current rules at their owner; use [decisions](../../../history/decisions/README.md) for lasting rationale and [runs](../../../runs/README.md) for handoff. Personal/global memory and installed plugin caches require explicit user authorization.

Report accepted lessons, rejected observations, out-of-scope proposals, chosen enforcement, why stronger options were unsuitable, evidence, checks, and remaining uncertainty.
