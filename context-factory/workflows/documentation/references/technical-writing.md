# Technical writing

For guides, skills, RFCs, PR descriptions, and commit messages, choose the purpose: a tutorial teaches with visible results; a how-to gives steps toward a goal; a reference organizes facts for lookup; an explanation covers mechanism, context, and tradeoffs. Link supporting detail without forcing every mode into one procedure.

Use current names, commands, and paths; verify technical claims using the owning source and behavior evidence when needed. Use present tense for current behavior and direct commands for steps. Place conditions and consequences before an action, use descriptive links and coherent headings, and keep each concept's name consistent. Use `.env.example` for variable names without copying secrets. A PR body leads with the problem and resulting behavior, followed by relevant validation and risks.

Apply the [prose pass](humanize-text.md). For durable artifacts use [documentation](../SKILL.md), including source authority and final checks; product UI copy follows the affected product and design guidance.
