# TypeScript best practices

Follow the [Clemora workflow adapters](../../shared/skill-adapters.md) and [operating contract](../../shared/agent-workflow.md).

Read [type system discipline](../principle-type-system-discipline/SKILL.md), the owning area guidance, and [API synchronization](../../shared/api-type-sync.md) for contract work. These are forward-looking rules for touched code, not a request to rewrite every existing assertion.

- Derive from Zod schemas, shared contracts, or generated Kysely types where those own the shape. Use inference and Pick/Omit/ReturnType/Awaited before duplicating an existing model.
- Treat external values as unknown until parsed. On the API, use the existing @hono/zod-openapi schemas and validated request values. Do not introduce a browser schema dependency merely to mirror a server schema without evaluating the existing ownership.
- Prefer discriminated unions to booleans plus unrelated optional fields. Narrow with discriminants, in, typeof/instanceof, or a guard that actually verifies its claim. Check exhaustive variants with never.
- Avoid new any, unchecked as casts, and non-null assertions used to silence missing proof. Return the parsed/narrowed value. satisfies checks a static shape; it does not validate network data. Literal as const is different from asserting unverified JSON.
- Use validated semantic brands or stronger tuple/range types when they eliminate a concrete ambiguity. Keep ordinary arrays when operations remain total; handle a legitimate missing result explicitly.
- Prefer named object arguments when positional values are easy to swap. Preserve a clear existing signature for a small scoped change.
- Keep mutable state local and derive values instead of synchronizing copies. Respect transaction and async lifetimes, including React effect cleanup.
- Use the existing diagnostic/error pattern with useful sanitized context. Do not log credentials, tokens, full private payloads, or invent an installed logger.
- Test observable behavior. Use actual integrations when integration behavior is the claim; mocks and compile-time types do not prove it.

Current examples: package controller schemas infer Content; shared catalog DTOs come from @event-management/contracts/catalog; Kysely DB is generated by pnpm db:generate. In contrast, `apps/web/src/lib/data/` still has handwritten DTOs, and `lib/http/request.ts` `request<T>` asserts the response type. Those assertions do not verify the response at runtime. Inspect and compare both sides of a touched contract, and improve a boundary only within the task's scope.

Run the closest package check and relevant behavior verification from the area skill. Preserve existing formatting in touched files rather than introducing a repository-wide style sweep.
