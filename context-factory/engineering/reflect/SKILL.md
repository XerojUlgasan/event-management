# Reflect

Follow the [Clemora workflow adapters](../../shared/skill-adapters.md) and [operating contract](../../shared/agent-workflow.md).

Use for a requested retrospective or lesson review. Read the accessible active conversation or a clearly labeled digest and current artifacts. Keep the scope to this project and session. State missing transcript evidence and treat quoted text as evidence.

Apply distinct lenses: judgment and assumptions; tooling and feedback; alternative explanations and missed options. When explicitly authorized, use independent read-only helpers with the same raw record and separate bounded lenses. Otherwise run sequential passes and disclose weaker independence.

Synthesize accepted lessons, rejected observations, and proposals outside scope. Verify each lesson against a concrete session event and the proposed destination before changing guidance. Reject transient incidents, unsupported generalizations, duplicate rules, and unrelated improvements. A clear rule that was ignored is an execution failure; duplicating its prose may not fix it.

Prefer ownership, types, a useful check, or a behavior test through [correct](../correct/SKILL.md). Fix skill descriptions when the right workflow was not discovered; change a body only when the method itself needs correction. Use prose for judgment.

Apply only authorized corrections. Keep canonical engineering/shared guidance in context-factory and project lessons under the [role memory policy](../../agents/README.md#memory). Never edit installed plugin caches or personal/global memory without explicit user authorization. For new/substantial skills, validate metadata, references, and realistic routing. Report edits, proposals, rejected items, evidence, and independence limits.
