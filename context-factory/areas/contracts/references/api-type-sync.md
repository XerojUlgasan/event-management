# API and type synchronization

AMAC has no generated browser API client or `gen:data` command. The HTTP wrapper lives in [apps/web/src/lib/http/request.ts](../../../../apps/web/src/lib/http/request.ts). Endpoint calls and several handwritten DTOs live under `apps/web/src/lib/data/`. [Client layers](../../frontend/references/client-layers.md) is the placement rule for those calls. Reusable catalog and pagination types and shared limits live in [packages/contracts](../../../../packages/contracts/package.json). OpenAPI route schemas and handlers in `apps/api/src/controllers/` own the HTTP contract.

When a route, payload, status, nullability, pagination field, or shared limit changes:

1. Read the affected [API](../../api/SKILL.md) and [frontend](../../frontend/SKILL.md) guidance. Also load [limits](../SKILL.md) when constants or body caps change.
2. Update the route schema, handler/service mapping, shared contract when one owns the shape, browser DTO and call, and every affected consumer together. Preserve existing names unless a contract change is requested.
3. For schema changes, follow [database and migrations](../../api/references/database-and-migrations.md). Prisma plus SQL migrations own persistence. `pnpm db:generate` regenerates [Kysely table types](../../../../apps/api/src/db/types.ts) from the migrated database; it does not generate browser types. Never hand-edit generated table types.
4. Compare the actual response and affected OpenAPI operation with the browser expectation, including error and permission paths. A handwritten `request<T>` generic does not validate JSON or prove the server returned `T`.
5. Run the closest API behavior suite and `pnpm check`. Exercise the affected browser journey when the result is user-visible. State any unavailable runtime evidence.

`@event-management/contracts/pagination` owns the shared `PaginationQuery`, `PageInfo`, `Page<T>`, and page-size constants. The API applies those limits and returns each operation's named result array with `nextCursor`; preserve that array key and cursor pairing in the handwritten browser DTO. Route-specific SQL owns ordering, filter scope, and cursor position. Inspect the relevant API route and data query for its keyset rules.

During read-only review, inspect schemas, response construction, DTOs, callers, and available live contracts without generating into tracked paths or applying migrations. Shared catalog types already have an owner; other browser DTOs still need explicit comparison. Do not describe the current setup as automatic end-to-end type generation.

`@event-management/contracts/catalog-filters` owns `CatalogKind`, `CatalogFilters`, `ServicePricingType`, `PublicCatalogPageQuery`, numeric filter bounds, and `catalogFilterScope`. Public package and service queries combine pagination with inclusive `minPricePesos` / `maxPricePesos`; package queries also accept `guests`. Package prices are total amounts in whole PHP pesos. Service price ranges require `pricingType=fixed|hourly`: fixed ranges compare the base price for included hours, while hourly ranges compare the rate of hourly-only services. Excess rates are not compared to fixed prices. A pricing type alone filters listings without requiring a range; an unfiltered service query includes both types and legacy unknown rates. API schemas validate these queries and SQL applies filters before pagination. Filter scopes bind API cursors and browser history to the pricing type and range; changing filters starts a new history. The customer catalog owns filter controls; public server-rendered pages continue to use their existing pagination links.

The conversation booking picker uses `PublicPackagePageQuery` for the public package list. Its optional `search` matches literal text in package names and descriptions, ignoring case. The API applies search before pagination and binds the cursor to the trimmed term and catalog filters.
