# Pages and application structure

- `apps/web/src/pages/index.astro` serves `/`, imports `styles/app.css`, and mounts `components/app/App.tsx` as a React client-only island. The React app owns its current in-page view switching; there is no separate Astro file for each workspace view.
- `src/pages/landing.astro` serves `/landing`, imports `styles/global.css`, and mounts `LandingScene.tsx` for the 3D experience. Scene models live in `components/scene/EventModels.tsx`; `docs/LANDING.md` documents this page.
- `components/app/App.tsx` wires auth and selects public, sign-in, admin, or customer views. `AppShell.tsx`, `Sidebar.tsx`, `pages/`, and `customer/CustomerDashboard.tsx` contain the corresponding workspace UI.
- The admin sidebar includes Customers and Staffs. Both show sample directories with clickable rows and read-only detail drawers; neither directory is connected to a staff or customer management API.
- The admin sidebar has a Services item backed by the service catalog API. `/` and `/landing` show the first three published services and packages in each section. `/catalog?type=services` and `/catalog?type=packages` are the public overview tabs; they append pages of 15 as the visitor scrolls. Package and service cards open full-screen previews. Service previews list published packages that include the service; package-specific inclusions and add-on prices appear in package previews.
- In the admin workspace, Packages has Packages and Archives tabs, and Services has Services and Archives tabs. The active tabs omit archived records; the Archives tabs show them from the admin catalog responses. These tabs do not appear in the customer workspace.
- Both signed-in workspaces open Account settings from the user menu. The customer Messages tab and the admin Messages workspace share PostgreSQL-backed conversations through `/v1/messages` and `/v1/admin/conversations`. Both poll every five seconds, show unread counts, and mark the other side's messages read when a thread is opened.
- The shared published package preview offers Book now on the public, landing, catalog, and customer surfaces. The form keeps a draft in the current browser tab through sign-in and requires explicit review before submission. Customer My events and manager Bookings list the same persisted booking requests; they do not represent confirmed events.
- Keep page-specific components and content in `apps/web`. Use `@event-management/ui` for reusable presentational components; consult the packages skill before changing that package.
- Check `docs/FEATURES.md` before implementing business workflows. Its first-release list is intended scope; current mock screens and demo data are not proof of backend implementation.
