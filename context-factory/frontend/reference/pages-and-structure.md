# Pages and application structure

- `apps/web/src/pages/index.astro` serves `/`, imports `styles/app.css`, and mounts `components/app/App.tsx` as a React client-only island. The React app owns its current in-page view switching; there is no separate Astro file for each workspace view.
- `src/pages/catalog.astro` serves the separate `/catalog` public catalog route. The old 3D `/landing` page and scene have been removed.
- `components/app/App.tsx` wires auth and selects public, sign-in, admin, or customer views. `AppShell.tsx`, `Sidebar.tsx`, `pages/`, and `customer/CustomerDashboard.tsx` contain the corresponding workspace UI.
- The System Administrator sidebar includes a combined Staff & Customers directory backed by `/v1/admin/users`, with read-only detail drawers. Staff have a separate read-only workspace for booking requests and published packages and services.
- The admin sidebar has Services and Venues items backed by their respective catalog APIs. On the public `/` page, featured packages, services, and venues appear in that order. Each View more control opens an overlay with the full paged catalog; `/catalog` remains available directly. Cards open full-screen detail previews, and closing a detail returns to the catalog overlay. Service previews list published packages that include the service; package-specific inclusions and add-on prices appear in package previews. The Venues admin page manages versioned drafts, publication, and archives; new publication requires one or more of at most 10 uploaded photos and positive minimum/maximum capacity. Migrated published venues can have null capacity and no photos. Venue fields include title, location, description, optional editable categories, capacity, and photos; Google Maps pinning is deferred until an API key is available.
- In the admin workspace, Packages has Packages and Archives tabs, and Services has Services and Archives tabs. The active tabs omit archived records; the Archives tabs show them from the admin catalog responses. These tabs do not appear in the customer workspace.
- Both signed-in workspaces open Account settings from the user menu. The customer Messages tab and the admin Messages workspace share PostgreSQL-backed conversations through `/v1/messages` and `/v1/admin/conversations`. Both poll every five seconds, show unread counts, and mark the other side's messages read when a thread is opened.
- The shared published package preview offers Book now on the public page, catalog overlay, separate catalog route, and customer surfaces. The form keeps a draft in the current browser tab through sign-in and requires explicit review before submission. Customer My events and manager Bookings list the same persisted booking requests; they do not represent confirmed events.
- Keep page-specific components and content in `apps/web`. Use `@event-management/ui` for reusable presentational components; consult the packages skill before changing that package.
- Check `docs/FEATURES.md` before implementing business workflows. Its first-release list is intended scope; current mock screens and demo data are not proof of backend implementation.
