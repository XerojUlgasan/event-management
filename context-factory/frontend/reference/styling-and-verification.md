# Styling and verification

- `src/styles/app.css` styles the root React app and public catalog overlays, including `src/styles/public-catalog.css`. Shared tokens live in `packages/theme/src/theme.css`; shared component styles live in `packages/ui/src/styles.css`.
- CSS-only changes follow the [mandatory package reuse workflow](../../shared/shared-packages.md#required-workflow-for-every-ui-change). Reuse existing theme tokens and shared component styles. Keep page layout rules in app styles; put reusable visual variants in the owning UI component and its styles instead of duplicating its base rules in app CSS.
- The root workspace uses vendored images and fonts in `apps/web/public/`. Follow the touched page's existing asset and CSS pattern. Use semantic elements, accessible names, keyboard behavior, and responsive layouts when changing interactive UI.
- `CatalogCanvas`, `CatalogSections`, `CatalogWidgetContent`, and `CatalogMarkdown` from `@event-management/ui` own the shared catalog frame and saved widget/Markdown rendering; entity composition and media URL resolution stay in `apps/web/src/components/catalog/CatalogContent.tsx`. The frame fills its container without a width cap or horizontal frame padding. Both editor and saved grids use the exported `CATALOG_GRID` metrics: 12 columns, 52px rows, 12px gaps, and 12px grid padding. `CatalogGridGuides` and `CatalogGridRuler` from `@event-management/ui` show these actual cells and column numbers; do not restore a fixed-size decorative background. Section rows grow automatically to `max(y + h)`, or zero when empty, and the displayed count follows drag/resize previews before committing. Row count is derived from saved widget coordinates rather than a separate section field. Narrow screens identify their one-column stacked display and the saved 12-column layout separately. Widget controls expose saved column, row, and span. Shared widget height and starting-row limits come from `@event-management/contracts/limits/catalog`; enforce them for keyboard, pointer resizing/movement, and widget creation. The editor's add-widget toolbar sits above the canvas, leaving its full width available. The shared inline-size container query stacks widgets below 520px, and catalog headings use container-relative sizing. Editor and preview scroll areas and the public document reserve stable scrollbar space so short and long pages keep the same width. Compare editor, preview, and public widget content rectangles at the same viewport; embedded booking views adapt to their containing area. Photos/videos use `object-fit: contain`; rendered widget overflow is clipped with no internal scrolling, including Markdown tables and code blocks.
- Widgets move by their header and resize from a bottom-right corner grip. The header appears on hover or keyboard focus and stays visible on touch layouts; widget outlines and resize grips remain visible. The editor disables automatic grid compaction so saved vertical gaps remain visible in previews and public pages. `react-grid-layout`'s stylesheet hides `.react-resizable-handle` with `opacity: 0` until the item is hovered and draws its own 20px grip, so local overrides in `package-editor.css` must outrank `.react-grid-item > .react-resizable-handle`. Keep the handle at least 24px, visible at rest, and above widget media. Editor resizing is disabled below the editor's 520px measured width, where widgets stack and reorder with arrow buttons; the shared saved-content renderer independently stacks below 520px of its container width.
- The canvas always uses the shared widget renderer, including captions. Widget controls overlay the content rather than reducing its dimensions. Edit Markdown opens a separate native dialog with `MDEditor`; authoring may scroll there while the rendered canvas clips to the saved widget size. Keep sanitized Markdown rendering shared through `CatalogMarkdown`, and verify dialog dismissal, focus restoration, undo, and the rendered result when changing authoring behavior.
- Inspect the current web package scripts, then run `pnpm --filter @event-management/web check` for Astro/TypeScript diagnostics and `pnpm --filter @event-management/web build` for a production bundle. For changes to shared components, also run the package checks from the packages skill.
- Run `pnpm --filter @event-management/web test:catalog` for catalog SSR markup coverage, including sanitized Markdown, media attributes, editor autoplay suppression with caption parity, private package content, legacy null fields, and empty media. These checks do not replace browser inspection of rendered layout or native video playback.
- For visible behavior or layout, inspect the actual page at the relevant route and viewport when a browser is available. A successful build alone cannot verify interaction, responsive layout, or login behavior. State what was and was not exercised.
- Run `pnpm check:design` after web/UI changes to check native control migration, public package imports, and authored color literals. It does not detect every duplicated composition or verify component fit, keyboard behavior, or rendered layout. Shared color choices live in `packages/theme`; page-specific composition remains in the app. The [whole-web refactor ledger](../../agents/senior-developer/reference/web-ui-refactor.md) records the migration and its evidence.
- Before delivery, complete the workflow's [reuse and verification audit](../../shared/shared-packages.md#completion-audit). Name the reused exports/tokens, explain any local alternative, and report the applicable checks and rendered states exercised.
