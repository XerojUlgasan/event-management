# Shared catalog canvas

Packages, services, and venues share the editor in `apps/web/src/components/app/pages/CatalogEditor.tsx`. It owns section ordering, the 12-column drag/resize grid, mobile reorder controls, sanitized Markdown, photo/video upload settings, local file previews, upload-on-save, and error feedback. Entity screens supply metadata, validation, persistence, and customer/card previews. `CatalogSections.tsx` renders saved widgets for all three catalogs; `CatalogPreview.tsx` provides service and venue details.

Packages publish directly on save. Their stored catalog description is separate from Markdown widgets. Services and venues are also flat records and save directly as public active records. Service saves require a name, description, positive whole-peso hourly rate, and a canvas photo. Venue saves require a name, location, description, and a positive maximum guest count; photos are optional. Migrated service rates and venue guest limits may be null for reads; save validation requires complete current inputs. Optional omitted canvas sections remain unchanged on update. All catalog photos use canvas widgets.

Migration `20261102180000_flat_services_venues` preserves entity IDs, timestamps, current published metadata, and the selected canvas. If a listing has no current published version, the migration retains its latest content and archives the flat record. Previously archived listings remain archived. Unselected version pages and `service_versions`/`venue_versions` are dropped. Uploaded R2 objects are not deleted by the migration. Back up before deployment if version history matters, and inspect all pending migrations; the earlier `20261102130000_package_canvas` migration has separate package and booking-data impact.

Canvas images and videos use the upload-only catalog-media API and its file limits. Public media streaming requires a reference from a published, non-archived catalog record. An authenticated System Administrator preview can access that administrator's own pending uploads and uploads referenced by archived records. An unreferenced object can be deleted only after no catalog widget references it. See the [catalog media reference](../context-factory/api/reference/external-image-urls.md).

For focused verification, use `pnpm check`, `pnpm --filter @event-management/api db:validate`, and `pnpm --filter @event-management/api test:venues`; run `pnpm --filter @event-management/api test:packages` for shared package-canvas behavior. The API suites require their configured local PostgreSQL test setup. Browser behavior and production R2 availability require separate evidence.

The admin catalogs reuse `pages/CatalogCard.tsx` for image, title, description, labeled metadata, status, and compact footer actions. Their list views include search and Active/Archives tabs; Edit and archive actions operate on flat records, while preview and eligible deletion remain available from the card actions.
