# Unstaged changes: previous and current

Snapshot: November 7, 2026. “Previous” refers to commit `b1ee3dd`; “Current” refers to the working tree, including new untracked files. This is a source comparison, not runtime verification.

| Area | Previous | Current unstaged changes |
| --- | --- | --- |
| **Booking details** | The original inquiry stayed separate from an editable “arrangement.” | Event details now live directly on the booking request. Administrators edit them there, with checks against overwriting newer changes. Internal notes are hidden from customers and ordinary staff. [Source (line 13)](../apps/api/src/services/booking-requests/details.ts) |
| **Customer change requests** | Customers submitted structured customization requests. Administrators approved or rejected them through a queue and Customizations tab. | That workflow is removed. Customers discuss changes through chat; administrators update the event details or package. Chat messages do not automatically change either. [Source (line 902)](../apps/web/src/components/app/BookingList.tsx) |
| **Package information** | Each inquiry kept a frozen copy of the package’s name, price, guest limit, and inclusions. | Requests show the **current linked package**. Editing a catalog package can therefore change what existing requests display. Guest-limit warnings also use the current maximum. [Source (line 25)](../apps/api/src/services/booking-requests/response.ts) |
| **Private custom packages** | There was no booking-specific private package editor. | Administrators can reuse the existing canvas editor to create a private copy and replace that booking’s package. Later edits update the same copy. The owning customer can preview it; public catalogs, other customers, and ordinary staff cannot access its private content. [Source (line 30)](../apps/web/src/components/app/BookingPackage.tsx) |
| **Quotations** | Quotes used the booking’s saved package price. Revisions carried the previous base and adjustments. | New quotes use the current package price and record the offered package/event terms. Changes make an offer outdated and block sending or acceptance. Revisions use current terms and require explicit review of carried-over adjustments. [Source (line 73)](../apps/api/src/services/quotations/quotations.ts) |
| **Dates and chat expiry** | Requests supplied a timezone. Pending customization requests could keep linked chat open beyond the event cutoff. | Date handling uses Asia/Manila. Linked chats close 24 hours after a known event end, without the pending-customization exception. Active requests without an end time keep their chat open. [Source (line 18)](../apps/api/src/data/messages/expire-conversations.ts) |
| **Photos, videos, and editor behavior** | Media retention mainly followed current canvas references. | Private copies receive independent uploaded media. Quotation history also protects referenced media from cleanup. Editors add discard/refresh confirmation, stale-save recovery, and focus restoration. [Source (line 30)](../apps/api/src/services/booking-requests/custom-package.ts) |
